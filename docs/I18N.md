# 原库是怎么显示中文的（EZX 语言包机制）

> 本文所有结论都有实机或二进制证据，不做推测。关键实验过程见文末「怎么验证的」。

## 1. 结论速览

| 问题 | 答案 |
|---|---|
| 中文存在哪 | `EZX_RES_STRING_PATH=/usr/language/string/<locale>/*.qm`（本机 `zh-cn/` 下 27 个 .qm） |
| 谁加载 | `libezxappbase.so`（含 `QTranslator` / `installTranslator` / `.qm` / `lib_` / `common_` / `DefaultLanguage` 字符串），进程启动时装到 `QApplication` 上 |
| 原库怎么取 | `QObject::tr("TXT_RID_CBUTTON_ALL", "All")` —— 注意是 **静态** `QObject::tr`，context 固定为 `"QObject"` |
| 界面为什么先是英文 | 注册表里 `Name = All / Office / Multimedia ...` 本来就是英文；不调 `tr()` 就显示英文 |
| 哪些被翻译 | **只有文件夹名**被翻译。应用名、快捷方式名一律返回注册表 `Name`，原库没有 tr 调用 |
| 我们怎么复刻 | `amFolderLocalName()` 查表 → `QObject::tr(key, comment)`，实机输出`全部/办公/多媒体/其它/游戏/自定1` |
| 要不要自己写中文表 | **不需要**。用原库同样的 `key` 和 `comment`，Qt 就能从原厂语言包里取到同样的译文 |

## 2. 运行时环境（am 启动脚本里定死的）

```sh
export EZX_RES_STRING_PATH=/usr/language/string     # 字符串资源根目录
export EZX_LANG=/usr/language/
export QTDIR=/usr/lib/ezx
export LD_LIBRARY_PATH=$QTDIR/lib:/usr/language/vui/english/lib:/usr/language/vui/mandarin/lib:...
export EZX_RES_ICON_PATH=/usr/data_resource/icon     # 图标资源（不是 qm）
export EZX_RES_FONT_PATH=/usr/language/fonts         # 字体（中文能显示的前提）
```

要点：
- **字符串**与**图标**是两套资源，路径不同（`string` vs `icon`）。中文显示不出来时先查
  `EZX_RES_FONT_PATH/../fonts/fontdef.cfg` 有没有中文字体，再查 qm。
- 语言目录是三套并列：`en-gb / zh-cn / zh-hk`。

## 4. .qm 文件格式（实测，Qt2.3.8 用 Qt3 风格格式）

```
偏移 0x00  16 字节 magic = 3c b8 64 18 ca ef 9c 95 cd 21 1c bf 60 a1 bd dd
偏移 0x10  开始是若干「段」，每段 = tag(1B) + 长度(4B, 大端) + 数据
```

三段，顺序固定：

| tag | 名称 | 结构 |
|---|---|---|
| `0x42` | Hashes | `(hash u32 BE, offset u32 BE)` × N，按 hash 排序 |
| `0x69` | Messages | 数据区；每条 = `flag(0x03) + 长度(4B BE, 字节数) + 译文(UTF-16BE)` |
| `0x2f` | Contexts | 表 + 数据区；数据区每条 = `len(1B) + context 名(ASCII)` |

实测 `am_zh-cn.qm`：Hashes 1264B(158 条) / Messages 3835B / Contexts 866B(27 个 context)。

**最关键的一点**：消息里**只存 `hash` 和`译文`，不存英文源串**。

```
0x50A: 03 | 00 00 00 08 | 72 48 67 43 65 b9 00 3a   →  "版权方:"
0x51D: 03 | 00 00 00 04 | 57 df 00 3a               →  "域:"
0x52C: 03 | 00 00 00 0a | 59 1a 5a 92 4f 53 4f e1 60 6f → "多媒体信息"
```

所以在 .qm 里 `grep "All"` / `grep "TXT_RID_CBUTTON_ALL"` **搜不到是正常的** ——
英文源串在编译期就被哈希掉了。不要因为搜不到就以为找错了文件（这一条踩过坑）。

`am_zh-cn.qm` 的 158 条译文里没有任何英文串，全部是中文/格式串，反证了上面这条。

> 附：`hash` 的具体算法本轮没有逆向出来（试过 ELF hash / djb2 / sdbm 以及
> `key + 0x04 + comment` 的拼接形式，都对不上）。**但这不影响复刻**：我们只负责
> 传对的 `key`/`comment`，哈希由 Qt 的 `QTranslator` 内部算，不需要我们自己实现。

## 6. context 到底是哪个？—— 实验定论

原库 `AM_AppObject` **没有 `Q_OBJECT`**，所以它没有成员 `tr()`，只能调静态
`QObject::tr()`，于是 **context 恒为 `"QObject"`**。

实机 6 组对照（`touch /ram/tmp/am_debug` 后重启 am 采集）：

```
[i18n] cb839c8f-... key=TXT_RID_CBUTTON_ALL cmt=All
       QObj.tr='全部'            ← QObject::tr(key,cmt)      命中
       ctxAMAppObject='全部'      ← translate("QObject",...)  命中(同一件事)
       AMObj.tr='All'            ← translate("AM_AppObject",...) 未命中
       tr(cmt)='All'             ← QObject::tr("All")         未命中
```

结论：
1. 条目挂在 **context `QObject`** 下（不是 `AM_AppObject`）。13 个文件夹名全部如此。
2. `key` 必须是 `TXT_RID_*`；把 key 换成英文注释 `"All"` 就不命中。
3. Qt2.3.8 的 `QObject::tr(s, comment)` 在无翻译构建里第二个参数被完全忽略；
   有翻译时 comment 参与 `QTranslatorMessage` 的哈希键构造，所以**comment 要和原库填一致**
   （我们表里存的就是原库字面池里的英文注释）。

## 7. 应用名为什么不翻译

- 证据一：整个 `orig_local.so` 里没有 `Contacts` 字符串，`Camera`/`Bluetooth` 出现但另有用途。
- 证据二：`getName` 的 `Application` / `Shortcut` 分支里，除了 SETUP 运营商名和
  「下载管理器」这两个特例，其余路径都直接 `return FName`。
- 证据三：注册表 `Name` 字段就是英文（`Name = All`），而界面英文与之逐字一致。

所以"应用名显示中文"在**原厂行为里不存在**，要实现它属于**增强**，两条路：
1. 从各模块 qm 里找出应用名对应的 key（原厂若没做就是没有），只能自建表；
2. 自建 `AppID(UUID) → 中文` 表，写进 `amFolderLocalName` 同款查表逻辑。

## 8. 我们的实现（`src/AM_AppObject.cpp`）

```cpp
struct FolderNameEntry { const char* uuid; const char* key; const char* cmt; };
static const FolderNameEntry g_folderNames[] = { /* 上表 8 条 */ };

QString amFolderLocalName(const QString& uuid)
{
    if (uuid.length() != 36) return QString::null;      /* 热路径快速排除 */
    /* 结果缓存：命中过就记住，空串表示"查过没译文" */
    ...
    QString t = QObject::tr(e->key, e->cmt);
    if (t.isEmpty() || t == QString::fromLatin1(e->key))
        return QString::null;                            /* 无译文 → 回落 FName */
    return t;
}
```

两个必须保留的细节：
- **回落判据**：没装语言包时 `tr()` 会把源串原样返回（`"TXT_RID_CBUTTON_ALL"`），
  比英文还难看，必须判定并回落 `FName`。
- **缓存**：`getName()` 每帧每图标都会被调，`tr()` 要遍历翻译器链表，别每次都做。
